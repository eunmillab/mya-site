쇼핑몰 분류를 옮겼는데 저장이 안 됐을 때

화면에선 옮겨진 분류가 서버엔 저장되지 않던 문제를, 네트워크 요청으로 성공을 판단하는 방식으로 풀었어요.

무슨 일이 있었나요

쇼핑몰 메뉴의 「연구실」을 누르면 옛 분류가 나오고, 실제 상품 3,865건이 붙은 새 8대분류는 메뉴에 없었어요. 분류가 두 벌로 존재했어요.

카페24 분류 트리는 끌어다 놓기만 되고 상위 분류를 바꾸는 입력칸이 없었어요. 자동화 도구로 끌어다 놓아도 트리가 움직이지 않았어요.

왜 그랬나요

트리 객체를 직접 잡아 옮기면 화면은 바뀌는데, 「분류이동저장」을 눌러도 서버로 요청이 나가지 않았어요. 카페24가 자기 드롭 콜백 안에서 변경을 기록하기 때문이었어요. 화면이 바뀐 것만 보고 성공이라고 두 번 잘못 판단했어요.

이렇게 바꿨어요

트리의 드롭 콜백을 직접 부른 뒤 저장 버튼을 눌러, 저장 요청(CategorySave)이 네트워크에 찍히는지로 성공을 판단했어요. 한 번에 다 안 옮겨지면 여러 번 반복했어요.

확인 창이 뜨는 일괄 처리(판매함 · 진열안함 등)는 자동화 도구가 누를 수 없는 창이라, 엑셀 일괄 수정이나 대표 클릭으로 돌릴 목록을 따로 만들었어요.

달라진 것

새 8대분류는 「연구실」 아래로, 옛 분류는 「미진열」 아래로 정리됐고, 상품 목록 페이지 제목이 「연구실 - 분류명」으로 바뀐 것까지 확인했어요. 헤더 메뉴 하나는 별도 메뉴 설정에서 오는 것으로 보여 미해결로 남겼어요.

할 일 체크가 근거 없이 끝나는 걸 막고 싶을 때

브라우저 한 장짜리 작업실을 로컬 업무 앱으로 다시 만들면서, 파일을 원본으로 두고 근거 없는 체크는 앱이 받지 않게 했어요.

무슨 일이 있었나요

챙겨는 아티팩트 한 장으로 돌던 작업실이라 실제 업무 폴더와 따로 놀았어요. 건마다 명세 · 작업지시 파일은 폴더에 있는데, 할 일 체크는 앱 안에서만 됐어요.

워크플로우엔 「근거 없는 완료 금지」 규칙이 있었지만, 사람이 지켜야만 지켜지는 규칙이었어요.

왜 그랬나요

원본이 둘이었어요. 파일과 앱 데이터가 따로 있으면 어느 쪽이 맞는지 매번 확인해야 해요.

이렇게 바꿨어요

디자인과 기능은 기존 판 그대로 옮기고, 로컬 Next.js 앱으로 다시 만들었어요. 업무 폴더의 파일이 원본이고 앱 DB는 색인이에요. 서버는 이 맥 안에서만 열려요.

체크리스트를 체크할 때 근거를 꼭 받아 md 파일에 다시 쓰고, 근거가 없으면 거부해요. 홈의 「급한 일」엔 결정 대기 · 승인 안 된 명세 · 같은 지적 3회를 모아 보여 줘요.

코드 리뷰 1회차 16건 중 13건을 반영했어요. 개발 서버가 모든 네트워크에 열리던 것, 항목 하나를 지우면 같은 id 두 개가 다 지워지던 것, 서버를 켠 채 백업하면 DB를 동시에 여는 것 같은 높은 위험부터 막았어요.

달라진 것

단위 테스트 60개와 브라우저 테스트 8개가 통과했고, 탭 5개를 기존 판과 390px · 1280px 폭으로 나란히 캡처해 대조했어요. 맥에 로그인하면 앱이 자동으로 켜져요.
